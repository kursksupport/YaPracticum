Описание API
Проект содержит REST API для работы с мероприятиями
Используемые технологии:
C#
.NET 9
ASP.NET Core Web API
Swagger

Эндпоинты:
Получить список всех мероприятий
GET /events
Возвращает все созданные мероприятия

Получить мероприятие по Id
GET /events/{id}
Возвращает одно мероприятие по его Id
Если мероприятие не найдено - возвращается 404 Not Found

Создать мероприятие
POST /events
Создает новое мероприятие
При успешном создании возвращается 201 Created

Обновить мероприятие
PUT /events/{id}
Полностью обновляет мероприятие по Id
Если мероприятие не найдено - возвращается 404 Not Found

Удалить мероприятие
DELETE /events/{id}
Удаляет мероприятие по Id
Если мероприятие не найдено - возвращается 404 Not Found
При успешном удалении возвращается 204 No Content

Модель Event
Событие содержит следующие ключевые поля:
TotalSeats - общее количество мест (обязательное при создании)
AvailableSeats - текущее количество доступных мест
Поведение:
  при создании: AvailableSeats = TotalSeats
  при бронировании: уменьшается на 1
  при отмене брони: может быть увеличено обратно

Создание брони
POST /events/{id}/book
Создает новую бронь для указанного мероприятия
Если бронь успешно создано - ответ 202 Accepted
Если мероприятие не найдено возвращается 404 Not Found
Нет доступных мест для бронирования - 409 Conflict

Получение брони
GET /bookings/{id}
Возвращает информацию о брони по её идентификатору
Если бронь найдена - ответ 200 OK
Если бронь не найдена возвращается 404 Not Found

Проверяются следующие правила:
поле Title обязательно
поля StartAt и EndAt обязательны
EndAt должно быть позже StartAt

Фоновая обработка:
После создания бронь получает статус Pending
Фоновый сервис периодически проверяет наличие необработанных броней
Для каждой брони выполняется искусственная задержка 2 секунды, после чего статус изменяется на Confirmed и заполняется поле ProcessedAt

Пример использования:
Создать мероприятие через POST /events
Создать бронь через POST /events/{id}/book
Получить бронь через GET /bookings/{id}
Сразу после создания статус будет Pending
Через несколько секунд статус изменится на Confirmed

Сценарий овербукинга
Событие: 2 места
Параллельные запросы:
5 пользователей вызывают POST /events/{id}/book
Результат:
2 брони - успешно (Pending → Confirmed)
3 брони - 409 Conflict (No available seats)

Потокобезопасность и защита от овербукинга
Для предотвращения ситуации, когда несколько пользователей одновременно бронируют последние места, реализована синхронизация критической секции
Используемые механизмы:

lock
Используется в BookingService:
lock (_bookingLock)
{
    // проверка мест
    // резервирование места
    // создание брони
}
Назначение: гарантирует, что только один поток одновременно выполняет проверку и изменение количества доступных мест, предотвращает состояние гонки 

SemaphoreSlim
Используется в фоновом сервисе обработки бронирований:
private readonly SemaphoreSlim _processingSemaphore = new(1, 1);
Назначение:
позволяет асинхронно синхронизировать обработку бронирований, заменяет lock, так как внутри используется await, защищает обновление состояния брони при параллельной обработке

Поддерживаются параметры фильтрации и пагинации:
  title Поиск по названию события (частичное совпадение, без учёта регистра)
  from События начинающиеся не раньше указанной даты
  to События заканчивающиеся не позже указанной даты
  page Номер страницы (по умолчанию 1)
  pageSize Количество элементов на странице (по умолчанию 10)

Как запустить проект:
Клонировать репозиторий
  git clone https://github.com/kursksupport/YaPracticum
Перейти в папку проекта
Запустить проект
  dotnet run
После запуска в консоли появятся адреса приложения.
Swagger доступен по адресу: https://localhost:<порт>/swagger

Запуск тестов:
Для запуска тестов выполните команду: dotnet test

Обработка ошибок:
Приложение использует глобальный middleware для обработки ошибок. Ошибки возвращаются в формате Problem Details (RFC 7807)
  Возможные HTTP-статусы:
  400 Bad Request
  404 Not Found
  409 Conflict
  500 Internal Server Error
