Описание API

Проект содержит REST API для работы с мероприятиями

Используемые технологии

C#
.NET 9
ASP.NET Core Web API
Entity Framework Core
PostgreSQL
Swagger

Эндпоинты

Получить список всех мероприятий
GET /events
Возвращает все созданные мероприятия
Получить мероприятие по Id
GET /events/{id}
Возвращает одно мероприятие по его Id
Если мероприятие не найдено — возвращается 404 Not Found

Создать мероприятие
POST /events
Создает новое мероприятие
При успешном создании возвращается 201 Created

Обновить мероприятие
PUT /events/{id}
Полностью обновляет мероприятие по Id
Если мероприятие не найдено — возвращается 404 Not Found

Удалить мероприятие
DELETE /events/{id}
Удаляет мероприятие по Id
Если мероприятие не найдено — возвращается 404 Not Found
При успешном удалении возвращается 204 No Content

Модель Event

Событие содержит следующие ключевые поля:
TotalSeats — общее количество мест (обязательное при создании)
AvailableSeats — текущее количество доступных мест

Поведение:

при создании: AvailableSeats = TotalSeats;
при бронировании: уменьшается на 1;
при отмене брони: может быть увеличено обратно

Создание брони
POST /events/{id}/book
Создает новую бронь для указанного мероприятия
Если бронь успешно создана — ответ 202 Accepted
Если мероприятие не найдено — 404 Not Found
Нет доступных мест — 409 Conflict

Получение брони
GET /bookings/{id}
Возвращает информацию о брони по её идентификатору
Если бронь найдена — 200 OK
Если бронь не найдена — 404 Not Found
Проверяются следующие правила
поле Title обязательно;
поля StartAt и EndAt обязательны;
EndAt должно быть позже StartAt

Фоновая обработка
После создания бронь получает статус Pending
Фоновый сервис периодически проверяет наличие необработанных броней
Для каждой брони выполняется искусственная задержка 2 секунды, после чего статус изменяется на Confirmed и заполняется поле ProcessedAt

Пример использования
1. Создать мероприятие через POST /events
2. Создать бронь через POST /events/{id}/book
3. Получить бронь через GET /bookings/{id}

Сразу после создания статус будет Pending
Через несколько секунд статус изменится на Confirmed

Сценарий овербукинга
Событие: 2 места
Параллельные запросы:
5 пользователей вызывают POST /events/{id}/book

Результат:
2 брони — успешно (Pending, Confirmed);
3 брони — 409 Conflict

Потокобезопасность и защита от овербукинга

Для предотвращения ситуации, когда несколько пользователей одновременно бронируют последние места, реализована синхронизация критической секции

SemaphoreSlim
Используется в BookingService
Назначение:
гарантирует, что только один поток одновременно резервирует место;
предотвращает состояние гонки;
позволяет безопасно использовать await внутри критической секции

SemaphoreSlim в фоновом сервисе
Используется в сервисе обработки бронирований
Назначение:
синхронизирует параллельную обработку броней;
предотвращает одновременное изменение состояния одной и той же записи

Поддерживаются параметры фильтрации и пагинации
title
Поиск по названию события (частичное совпадение)
from
События начинаются не раньше указанной даты
to
События заканчиваются не позже указанной даты
page
Номер страницы (по умолчанию 1)
pageSize
Количество элементов на странице (по умолчанию 10)

Как запустить проект
Требования
Для запуска проекта необходимо:
.NET SDK 9;
PostgreSQL

Настройка строки подключения
Перед запуском необходимо указать строку подключения в файле appsettings.json:

json
"ConnectionStrings": {
  "DefaultConnection": "Host=localhost;Port=5432;Database=eventapi;Username=postgres;Password=postgres"
}
При необходимости замените параметры подключения на свои

Создание базы данных
При первом запуске приложение автоматически создаёт необходимые таблицы PostgreSQL с помощью метода EnsureCreated()
Дополнительных SQL-скриптов выполнять не требуется.

Запуск
Клонировать репозиторий:

bash
git clone https://github.com/kursksupport/YaPracticum

Перейти в папку проекта
Запустить приложение:

bash
dotnet run

После запуска в консоли появятся адреса приложения
Swagger доступен по адресу:
https://localhost:<порт>/swagger

Запуск тестов
Для запуска тестов выполните команду:
bash
dotnet test
Все юнит-тесты используют Entity Framework Core InMemory Provider, поэтому для их запуска PostgreSQL не требуется.

Обработка ошибок
Приложение использует глобальный middleware для обработки ошибок.
Ошибки возвращаются в формате Problem Details (RFC 7807).
Возможные HTTP-статусы:
400 Bad Request
404 Not Found
409 Conflict
500 Internal Server Error
